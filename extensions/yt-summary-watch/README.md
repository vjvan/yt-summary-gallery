# YT Summary｜Chrome 繁中字幕與分頁收音（0.5.0）

這是既有 YT Summary 的 **Manifest V3 薄前端**，不是另一套翻譯模型。

- 原文字幕模式（V1）只處理能取得**英文原文字幕**的 YouTube `/watch` 影片。
- 原文取得、語意整理、術語表、翻譯與快取都由本機 YT Summary 負責。
- 原文字幕模式不收音；新增的 V2 分頁收音是獨立的手動實驗模式，不會自動啟用。不下載影片、不製作配音、不啟動摘要或圖卡任務。
- 支援全本機整片預譯，以及播放附近的近即時預譯；兩者都不保證零延遲。字幕缺失、登入限制或 YouTube 字幕來源變動仍可能失敗。

## 0.5.0：全本機整片預譯、逐句快取與真實進度

- **本機整片預譯預設開啟**，只對已配對、已勾選本機同意且已啟用的影片生效；後端 `session.processingMode` 必須再次確認為 `local`。雲端不採用整片模式，仍只在播放時做近距離預取並保留原批次／費用上限。
- 載入原文字幕後立即預譯，**暫停影片或切到別的分頁仍會耗用本機算力**。每支影片一次最多一批請求、每批最多 8 句；目前播放位置優先，然後依原文順序補齊。跳轉不丟棄正在處理的那一批，完成後才依最新位置排下一批。
- Popup 可取消「全本機整片預譯」改回播放附近模式。**切至原文模式會中止尚未完成的請求**，保留已完成字幕；全部停用、撤回同意、離開影片或頁面卸載會取消並清空工作。收音與 Discord 的手動授權／行為不變，不新增權限。
- 播放器上方顯示 **已就緒 X／總 Y 句、失敗句數／批數**。依實際成功的原文 ID 計算，不是請求次數乘 8；末批不足 8 句也正確。只有所有句子成功才標「全片預譯完成」。其他情況會明說仍有失敗，不以英文或缺句填滿進度。
- 後端回傳單句部分成功時，**7 句成功、1 句失敗會保留 7 句中文**，僅失敗句顯示原文；成功句、失敗句都核對原始 ID／時間，成功句另外核對原文。失敗批本輪不自動循環重試，會繼續預譯其餘批次。
- 可按「重試目前區段」或「重試下一個失敗區段」手動重試；新後端只補沒有成功快取的句子，不重做同批其他已完成句。再次品質拒收即停在失敗狀態；非品質暫時錯誤仍沿用有界重試，身分／費用等錯誤維持安全停止。
- 重新載入時可讀取後端與**影片原文／模型／版本／術語**匹配的 `cachedCues`。已快取句子立即計入進度，全片快取齊全時不再送翻譯請求；不能把「已載入快取」誤認成剛完成一次新模型翻譯。
- 全片完整時提供本人點擊的 **「下載完整雙語 SRT」**，使用原始句子時間與完整原文／譯文，與畫面分頁獨立。不裁切、摘要或用原文冒充未完成翻譯；未完成時不提供「完整」下載。透過本機 Blob 下載，不新增 `downloads` 權限或外部上傳。

### 升級與驗收

在 `chrome://extensions` 重新載入，確認 **0.5.0**，再重新整理 YouTube；原配對可沿用。重新開 Popup 確認整片預譯偏好與本機算力說明。第一輪可能耗時，**預設不保證零延遲或全部句子都能通過品質檢查**。自動模式仍需另外開啟；開啟後其他已啟用 YouTube 分頁也可能各自預譯。

自動化以實際 classic-script VM 測試：暫停啟動、單一 in-flight、seek 邊界優先、逐句部分成功與快取、1279 句且大於 1 MiB 的 cached session、原文／停用取消、雲端不擴張及完整 SRT。**VM 不是使用者真 Chrome 的端到端驗收**；實際 Chrome 重新載入、下載與新影片翻譯需另行確認。

## 0.4.2：本機單批品質拒收可恢復（歷史版本／播放附近模式）

以下「暫停等待播放、離開區段撤銷重試」描述的是 **nearby（播放附近）模式**。0.5.0 的全本機整片模式在暫停時也會處理本人按下的重試，並沿用上方整片排程規則；跳轉仍會撤銷尚未執行的手動重試授權，但不取消正在處理的批次。

- 只對後端明確回傳 `LOCAL_TRANSLATION_QUALITY` 且本工作階段為 `local` 的錯誤，保留工作階段與已完成字幕；未通過區段不算成功、不顯示錯譯，也不以英文冒充翻譯。
- 失敗區段改顯原文與「未翻譯」提示，不再自動重送同一批；播放進入其他 8 句區段仍可繼續。可按播放器上方「重試目前區段」主動開始一次重試操作；暫停時只排定，播放後才送出，再次被品質拒收仍等待本人再次選擇；只有此手動操作遇非品質暫時錯誤時，沿用至多 3 次失敗的有界重試，成功、新品質拒收、安全停止或跳轉即撤銷。離開該區段會取消尚未送出的重試。
- 播放器上方獨立顯示**本次工作階段的模型名稱**，不把 Popup「已啟用」當作每段翻譯成功。模型由後端決定，不會自動更換模型或回退雲端。
- 401／過期、取消、逾時、其他模型錯誤及雲端費用上限等原有停止／有界重試策略不變；不清除雲端已預留的失敗請求費用額度。
- **目前升級請重新載入擴充功能，確認 0.5.0，再重新整理 YouTube 分頁**；沿用配對，無新增權限，錄音與 Discord 路線不變。VM mock 驗證不等於真 Chrome／真模型已通過。

## 0.4.0：Discord 分頁直播翻譯（獨立實驗路線）

**不會自動加入 Discord、不讀聊天室、不發訊息，也不會自動開始收音。** 只支援 Chrome 網頁版 `https://discord.com/channels/<伺服器 ID 或 @me>/<頻道 ID>`；ID 必須是 Discord 17–20 位數 snowflake。桌面原生 Discord、手機版、邀請頁、嵌入頁與其他來源不支援。

### 安裝／本人驗收步驟

1. 啟動本機 YT Summary 與已安裝的本機翻譯／語音辨識模型；Discord 路線**拒絕雲端模式**，未就緒也不回退雲端。
2. 在 `chrome://extensions` 重新載入此擴充功能，確認目前版本 **0.5.0**。Discord 路線於 0.4.0 新增 `https://discord.com/channels/*` 網站權限；0.5.0 相較 0.4.0 不新增權限，原 `storage/activeTab/tabCapture/offscreen` 保持不變；Chrome 如要求確認，必須由使用者本人核准。原配對權杖可沿用。
3. 本人開啟有權處理的 Discord 頻道音訊，再點擴充功能。Discord 區塊會顯示**精確來源網址與分頁標題**、本機就緒結果。若配對或來源剛變更，按「重新檢查來源與本機就緒」。這一步不取得音訊。
4. 每次重新勾選收音同意，確認已取得適當參與者同意，再按「同意並開始此 Discord 分頁收音」。只擷取原分頁播放聲音，**不是麥克風、不是螢幕錄影**。
5. 按「開啟直播翻譯台」開啟本機 `/live?session=<id>`，可與 Discord 原分頁並排。**切到翻譯台、其他分頁或關閉 Popup 後，原來源仍會持續收音**；原分頁聲音透過 AudioContext 保持可聽見。
6. 隨時可從 Popup「立即停止 Discord 收音」、本機翻譯台停止或關閉來源分頁。來源離開原頻道也會停止；本機頁面停止狀態每 2 秒輪詢，無法連線／權限中斷會關閉音軌。6 秒無控制回應會由 offscreen watchdog 停止，不自動恢復。

**授權時序**：先在 Popup 做本機就緒預檢與建立空 offscreen document；手動開始時立即取得 `getMediaStreamId`，不在該手勢前先等慢網路 API。後端再確認本機模式與同意，成功後才由 offscreen 取得音訊。Chrome 的一次性 stream ID 數秒內會過期；若本機回應慢導致過期，會明確失敗並要求本人重新檢查／手動開始，不繞過權限或自動重試收音。

### 連續 PCM、延遲與限制

- 與 YouTube V2 的 12 秒 MediaRecorder 路線分開。Discord 使用獨立 **AudioWorklet 連續 PCM**，音訊 sample 計數作時鐘，不讀 YouTube 播放器、Discord 隱藏狀態或 Discord API。
- 能量閾值／停頓切句：保留約 **0.3 秒前置音訊**，目標 **3–6 秒**；連續說話最長 **8 秒**硬切。每段有獨立完整 WAV header、**PCM16 單聲道**，使用 AudioContext 原生取樣率（8–96 kHz）後交本機後端正規化。這是簡易能量式 VAD，不是能保證辨識所有低音量語句的語音模型；背景音樂／噪音、重疊說話或太小聲均可能影響斷句。
- 錄音與辨識分開：前一段辨識時仍持續收下一段；sequence 從 0 遞增，start/end 為樣本累計秒數（6 位小數）。確定由此能量門檻略過的安靜區段標為 `gapReason: silence`，不假裝是漏音。
- **一次只有一段辨識中，包含該段的待處理佇列最多 30 秒**。Popup 顯示待處理秒數與落後提示，工具列 badge 同步顯示；超過上限自動停止、清除未完成音訊，向翻譯台記錄 `queue-overflow` 與約略未處理秒數，不偷偷跳過句子繼續收音。失敗不做無界重試。
- 停止會關閉所有 tracks、清除記憶體音訊佇列並取消工作。原始 PCM/WAV 不存 Chrome storage，只保留恢復清理所需的 session metadata；service worker 重新啟動後不會自動恢復收音。
- 舊 YouTube 收音與 Discord 共用單一 offscreen，**雙向互斥**。切換收音模式會先結束另一模式的音軌；YouTube 既有字幕／12 秒收音邏輯保留。
- 目前沒有 Discord 原頁字幕 overlay；翻譯看本機翻譯台。不宣稱零延遲、不保證全場無漏字、沒有語者辨識或自動回覆／發送訊息。

**驗證範圍**：已用合成 PCM 經實際 worklet 程式的 VM 測試 8 秒硬切、樣本連續、前置音訊與停頓，並 mock 驗證連續收音、單一辨識、30 秒超載停止、來源守衛、背景不中斷、手勢／同意、共用 offscreen 互斥與 watchdog。**未連入真實 Discord、未擷取使用者音訊、未代核准權限；Mock 並不等於 Chrome/macOS 真實收音端到端已通過。**

## 0.3.0：全本機不限總批數

- 以後端 `status/session.processingMode` 與 `unlimited` 為準，不依使用者自行修改的設定判定。`local` 模式不套用舊的 10／50 批與每日雲端付費上限，`limits` 的 `null` 表示不限總數。
- Popup 顯示「**全本機、不按批次收費、持續翻譯至停止**」，隱藏雲端批次／片段欄位。保留每批 8 cue、一次 1 批與取消。**0.3.0／目前 nearby 模式**只做近距離預取，不主動跑完整片；**0.5.0 本機整片模式**會逐批補齊整片，兩種模式都不保證零延遲。
- 升級後重新載入擴充功能，再重新整理 YouTube。**原配對權杖保留，不需重貼**；開啟 Popup 會用原配對讀取目前狀態。已被舊版 10 批停止的工作需按啟用建立新工作。
- 本機字幕翻譯與音訊辨識／翻譯不送外部模型 API；仍須從 YouTube 取得原文或播放音訊，因此不是整個 YouTube 網站離線使用。只在後端明確設定為 `cloud` 時，才顯示雲端費用同意與原有上限。
- `translationReady` 優先於「有設定」判定就緒，未就緒顯示後端狀態訊息並停用啟用按鈕；本機未就緒、忙碌或失敗都不會自動切到雲端。就緒檢查不等於推論速度保證，首次載入模型仍可能較慢。

## 安裝與首次使用（需由使用者自行完成）

1. 在 YT Summary 專案啟動本機伺服器：`npm run dev`，預設 `http://127.0.0.1:3000`。
2. 開啟該伺服器的 `/watch` 頁面，取得 **Chrome 配對權杖**。模型 API key 只留在後端設定；不要貼入擴充功能。
3. 在 Chrome 網址列輸入 `chrome://extensions`，開啟「開發人員模式」。
4. 按「載入未封裝項目」，選取本目錄 `extensions/yt-summary-watch`（包含 `manifest.json` 的那一層）。
5. 重新整理已開啟的 YouTube 影片頁面。把擴充功能釘選到工具列較方便。
6. 在 YouTube 影片分頁點擴充功能，填入本機網址和配對權杖。支援 `127.0.0.1`、`localhost` 及自選連接埠，**不接受遠端網址、網址子路徑或 URL 中的權杖**。
7. 先測試連線確認模式：全本機不需設定批次上限；若使用雲端，建議先設 **2 批**驗收。閱讀並勾選畫面所示的本機處理或雲端傳送／費用同意，按「啟用並開始目前影片」。功能預設關閉、自動模式預設不勾選。
8. **本機整片模式**載入原文後就開始預譯，暫停也會繼續；**播放附近／雲端模式**需開始播放才請求翻譯。播放器上方顯示狀態與本機整片進度，畫面下方依影片時間顯示原文／繁中字幕。可手動關掉 YouTube 原生 CC，避免兩組字幕重疊。

**此擴充功能的自動化測試使用 mock，不會自行核准權限或送出付費翻譯。** 實際 Chrome 安裝、音訊授權及雲端費用同意必須由使用者確認。


## V2：無字幕分頁收音（實驗，需每次本人確認）

> 尚未以真實 Chrome 收音、OS 權限或 OpenAI API 做付費端到端驗收。Mock 測試不能證明實際收音已成功。全本機首次建議手動停止做短片段驗收；雲端保持預設 **2 段**。

1. 重新在 `chrome://extensions` 載入本目錄，確認目前版本 **0.5.0**。V2 自 0.2.0 起使用 `activeTab`、`tabCapture`、`offscreen`；0.4.0 另新增 Discord channels 網站權限，0.5.0 不新增權限。Chrome 若要求新增權限，須由使用者本人確認；不會替使用者自動核准。
2. 開啟本機 YT Summary `/watch`，複製配對權杖。Popup 填本機網址與權杖，先按 **「測試連線／儲存配對」**。這一步只呼叫狀態 API，不啟用翻譯、不收音，也不使用模型。
3. 確認狀態顯示「收音辨識已設定」。請開啟一般 YouTube `/watch` 影片，先播放並設定 **1 倍速**，不要在廣告期間開始。
4. Popup 可垂直捲動；往下找到 **「無字幕：分頁收音（實驗）」**。全本機不限總段數，雲端先保留 **2 段**上限。每次開始前都要重新勾選目前模式的音訊處理同意：本機辨識／翻譯不送外部 API，雲端則明確同意 OpenAI 辨識與翻譯費用，再按開始。此同意不儲存，也不沿用字幕模式的同意。
5. 收音區按鈕旁有專屬狀態訊息：檢查中、錯誤原因、已啟動。播放器另有 **「收音逐字稿（延遲）」**面板。每段完整 **12 秒** WebM，最多 **2 MB**，每段都重建 `MediaRecorder`，不是不可獨立解碼的裸 timeslice 片段。
6. **一次只允許 1 段待辨識**：辨識期間不新增錄音，可能留下未收錄空段，不是連續逐字字幕。結果依原影片時間標記，晚到的字幕只出現在逐字稿面板，不會假裝與當下說話同步。點時間戳可回放已辨識片段；只有播放到 cue 本來的時間才覆蓋繁中字幕。
7. 暫停、跳轉、非 1 倍速、廣告、切換分頁／離開 Chrome 視窗、導航、關閉或達限，都會停止收音與音軌，丟棄未完成片段。再次開始須本人重新手動同意。回放時間戳也會停止正在進行的收音。
8. 按 Popup「停止分頁收音」、面板「停止收音」或「全部停用」皆可停止。失敗不會自動重試音訊；本機不回退雲端，已送出的雲端 API 仍可能計費。

**聲音不應消失**：offscreen 使用 `AudioContext` 把被擷取的分頁音訊重新接到輸出。只傳 `chromeMediaSource: tab` 且 `video: false`，不要求麥克風。控制時鐘中斷約 2.5 秒會由 watchdog 停止音軌。

### V2 額度與精度限制

- 全本機不限總段數，向後端送 `maxChunks: 0`；只有後端確認全本機不限才可接受 0。雲端預設 2 段、可選 2–20 段，仍受後端單次／每日更低上限限制，段數不是金額。
- 即時回放面板僅保留**最近 100 個片段／500 句（先達者）**，舊字幕與 DOM 會移除，避免長時間記憶體持續增加。這只限制回放視窗，不停止收音或套用總段數上限。
- V2 與 V1 不同時啟動；開始分頁收音會停用原文字幕自動翻譯，避免重複處理。
- 只支援前景、一般桌面 YouTube、英文語音、1 倍速。不可當作無延遲直播翻譯或完整逐字稿保證。
- 來源時鐘統一至 6 位小數；取樣與訊息延遲仍使邊界存在誤差，不能宣稱逐字時間精確或無損音質。
- 初次錄音需驗證 Chrome／macOS 權限、分頁音訊回放、12 秒 WebM 經後端 ffprobe 的真實相容性，以及停止後音軌確實結束。本次尚未執行此驗收。

## V1 原文字幕：模式對照與共同行為

**整片（full）模式**是 0.5.0 已同意本機處理後的預設。**播放附近（nearby）模式**是取消 Popup「全本機整片預譯」後的本機模式，以及所有雲端模式；下列 nearby 規則不適用於整片預譯。

- **手動模式**：啟用目前影片；切到另一支影片後須再按啟用。手動啟用新分頁會結束先前手動啟用的工作。
- **自動模式（另行 opt-in）**：功能啟用期間，已開啟及之後開啟／切換的 YouTube 影片，**整片模式載入後即可開始，即使暫停／在背景**；**nearby／雲端模式在前景播放時才開始**。會沿用已同意的處理模式；本機不限總批數，雲端保留已同意上限，沒有另外逐片詢問。不會自動啟動收音。
- **預譯**：兩種模式都先處理目前位置的 8-cue 固定批次。**nearby／雲端**僅在相鄰下一批的起點進入約 30 秒範圍時預取，不從頭跑完整片；**本機整片**則在目前位置就緒後依原文順序補齊其他批次。每批實際時長依原文而異；均為一次最多一批，不每秒 POST。
- **暫停／分頁在背景**：**nearby／雲端**停止發出新字幕和翻譯請求，已發出的請求仍可能完成、雲端仍可能計費；**本機整片**繼續逐批預譯並耗用本機算力。兩種模式的畫面字幕都只依影片時間選頁，不因背景翻譯自行跳頁。
- **快轉／倒轉**：以影片 `currentTime` 重選畫面字幕，已翻好的片段直接重用。**nearby／雲端**取消尚在處理的舊位置請求；**本機整片**保留正在處理的批次，完成後優先處理最新位置。雲端取消不能保證供應商免計費。
- **倍速**：依影片時間而非牆鐘時間同步，無固定秒數倒數。
- **結尾與空白段落**：嚴守原文 cue 的 `start <= time < end`，不把前一句留在空白段落。
- **廣告**：看到播放器 `ad-showing` / `ad-interrupting` 標記時，不顯示覆蓋字幕也不發新請求。YouTube DOM 改版時需重新驗收。
- **關閉**：播放器上的「關閉」停止這支影片、清空畫面字幕，即使自動模式開啟也不在同一支影片重新啟用。Popup「全部停用」會停止全部工作。
- **字幕切換**：繁中＋原文、繁中、原文。原文模式會取消尚未完成的請求、不再新增翻譯，已完成字幕仍保留。
- **錯誤與費用**：429 到上限立即停止新請求；非品質的 503／暫時性錯誤最多重試至 3 次失敗；本機明確品質拒收則隔離失敗批，必須本人重試，不會自動循環。本機沒有總批數／每日付費上限，也不按批次收費。**僅雲端**每片預設 10 批、可設 1–50 批，仍受後端更低的單片／每日上限限制；批次不是金額。
- **雲端保守計數**：失敗或取消可能已付費，擴充功能會保留其批次預留；成功回傳 `cached: true` 才釋放預留。因此可能提早停止，但不應超過使用者同意的請求上限。重新按啟用建立新 session 會重設單次上限，後端每日上限不會重設。
- 無字幕需另用手動分頁收音。直播、Shorts、手機版 YouTube、離線播放整個 YouTube 網站與任意來源語言不在本次驗收範圍。

## 隱私與權限

Manifest 使用 `storage`、`activeTab`、`tabCapture`、`offscreen`。`activeTab` 是指定 `targetTabId` 的官方授權要求，只有使用者點擴充功能才能取得；`offscreen` 以 `USER_MEDIA` 持有該次分頁音訊。網站權限限 YouTube、Discord channels 與本機 loopback，無麥克風、螢幕錄影、`debugger`、`desktopCapture`、`scripting`、`<all_urls>` 或遠端程式碼。

- 本機配對權杖存於此 Chrome profile 的 `chrome.storage.local`，設定為 `TRUSTED_CONTEXTS`，不透過 Chrome Sync 同步，content script 拿不到權杖。此儲存本身不是額外的加密保險箱，應保護本機帳號與 Chrome profile。
- Content script 不監聽網站 `postMessage`，不把權杖插入 DOM，不接受網站指定的 fetch URL。
- Discord 僅新增固定 POST `/api/live/session`、`/api/live/chunk`（multipart）、`/api/live/session/{id}/stop` 及 GET `/api/live/session/{id}`，同樣使用 loopback 配對權杖；不讀取或使用 Discord token、聊天 API。
- Service worker 驗證 extension sender ID、YouTube 主 frame 與當前 tab 影片 ID，且只代理固定 POST 路由：`/api/watch/session`、`/api/watch/window`、`/api/watch/session/{id}/stop`，以及固定 GET／DELETE 路由 `/api/watch/jobs/{uuid}`。V2 另僅固定開放 GET `/api/watch/status`、POST `/api/watch/audio/session`、POST `/api/watch/audio/chunk`（multipart）與 POST `/api/watch/audio/session/{id}/stop`。網站不能自行指定路由、方法或 HTTP headers。
- 慢工作使用 `Prefer: respond-async` 建立 job；每 1.5 秒以短 HTTP 請求查詢進度，而不是等待一條 90 秒長 fetch。每次 HTTP 請求最長 25 秒、整體工作最長 120 秒；只在 job 存續期間呼叫 Chrome API 保持 worker 活動，取消時以 DELETE 清理 job。仍需真實 Chrome 驗證長工作與意外終止恢復。
- HTTP 目的地只允許 `127.0.0.1` / `localhost`；禁止重新導向、cookie credentials 與任意 headers。
- 字幕及模型輸出以 `textContent` 顯示於封閉 Shadow DOM，不使用 `innerHTML`。
- 本機模式：V1 原文字幕與 V2 另行同意的音訊片段都在本機處理，不送外部模型 API。雲端模式：V1 會送字幕、標題、前後文及術語；V2 另行同意後由本機後端送 OpenAI 辨識與翻譯。不傳影片畫面或麥克風音訊。

## 0.4.1：完整長字幕、短頁顯示

- 只調整 YouTube 原文字幕路線的畫面呈現，不修改完整原文／譯文、原 cue 時間、翻譯批次或音訊／Discord 路線；**沒有新增權限**。
- 長字幕依原 cue 時段與文字長度依序分頁，通常每頁約 32 個中文字的顯示量，窄播放器會再縮短。每種語言目標最多約兩行；原文與繁中各自分頁，頁碼顯示於現有上方工具列，不以摘要、省略號或截斷取代完整內容。
- 分頁是原字幕時段內的近似顯示，不是假設有逐字對齊時間。暫停時停在當頁；倒帶／跳轉時依影片時間重新選頁；切換字幕模式不重設影片時間。頁碼旁 `*` 表示原時段短、單頁閱讀時間較密集，可在本機 `/watch` 使用「暫停看本句全文」與完整逐字稿閱讀。
- 所有頁面的文字依序串回，必須與完整原文／譯文完全一致；英文平台名稱、標點、空白和 Unicode 字元不刪除。這是可讀性調整，不代表翻譯語意已通過真人品質驗收。
- **升級方式：**在 `chrome://extensions` 找到已載入的 YT Summary，按「重新載入」，確認目前版本為 **0.5.0**（包含此 0.4.1 顯示修正），再重新整理原 YouTube 分頁；原配對保留。只重新載入擴充功能不會替已存在的 content script 更新程式。若正在使用手動收音，先自行停止，再重載；本次不需要核准新的網站或收音權限。
- 開發驗證新增長句完整重組、原 cue 時鐘、暫停／跳轉、雙語模式、TypeScript 與擴充功能 helper 行為一致性。隔離合成頁面的渲染測試不能取代使用者 Chrome／真影片驗收。

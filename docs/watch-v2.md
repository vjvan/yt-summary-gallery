# YT Summary V2：分頁音訊辨識與繁中翻譯（實驗版）

更新：2026-09-05

**先選對模式：**有英文原文字幕時，優先用 V1「繁中同步字幕」；字幕拿不到時，才手動開啟 V2「分頁收音」。V2 是有延遲的收音逐字稿，不是零延遲字幕或連續完整轉錄。

## 1. 更新與配對

1. 本次已更新的本機入口為 `http://127.0.0.1:3000/watch`。保持現有服務開啟，不要另啟動第二個程序占用相同連接埠。程序關閉後，可在 `/Users/vjvan/yt-summary-gallery` 執行 `npm run start -- --port 3000`；修改程式後先執行 `npm run build`。若自行改用其他連接埠，配對時也要一起改。
2. 到頁面下方「Chrome 配對碼」，按「展開 Chrome 配對碼」。內容仍會遮蔽，直接按「複製配對碼」即可，不必顯示明碼。
3. 若已安裝 V1，在 Chrome 網址列輸入 `chrome://extensions`，找到「YT Summary」，重新載入新版擴充功能（版本 **0.2.0**）。新版新增分頁擷取相關權限；如 Chrome 要求重新允許，**由本人確認**。本次更新的資料夾為 `/Users/vjvan/yt-summary-gallery/extensions/yt-summary-watch`；若載入的不是這個資料夾，需要改載入此位置。
4. **重新整理 YouTube 影片頁面**，避免舊 content script 殘留。
5. 點 Chrome 工具列的擴充功能：將 `/watch` 下方顯示的「本機服務網址」填入「本機 YT Summary 網址」（**不含 `/watch`**），貼上配對碼，按「測試連線／儲存配對（不啟用翻譯）」。此步不開始翻譯或收音。

配對碼不是 OpenAI API key；模型金鑰只留在後端，請勿貼入擴充功能、網址或分享截圖。

### V1 先前連線失敗的原因

已修正 Next.js 將內部 request URL 正規化為 `localhost`、但瀏覽器 Host 使用 `127.0.0.1` 時，被原本過嚴的本機來源比對誤擋的問題。這不是字幕提示詞或配對碼本身失效；修正沒有開放遠端主機。若仍失敗，先確認新版伺服器已重啟、擴充功能網址／連接埠正確，再測試配對。

## 2. 首次收音：先測 2 段

1. 在 Chrome 開啟 YouTube `/watch` 影片，開始播放，設為 **1 倍速**，保持該分頁與 Chrome 視窗在前景，避開廣告。
2. 在擴充功能下方「無字幕：分頁收音（實驗）」保留預設 **2 段**。每段錄 **12 秒**，不是金額上限；仍受後端較低的單次／每日額度限制。
3. 閱讀並勾選**本次分頁音訊與 OpenAI 費用同意**，按「同意並開始本次分頁收音」。只擷取目前 YouTube 分頁的聲音，**不是麥克風，也不錄影**。
4. 播放器會出現「收音逐字稿（延遲）」面板。錄完一段後，音訊經本機送交 OpenAI 辨識英文，再使用既有術語與翻譯流程產生繁中。兩階段都可能計費。
5. 等結果出現後，點「時間範圍 ↻ 回放」可跳回對應片段；**回放會停止收音**。譯文只在原本對應的影片時間顯示，不會把晚到的文字冒充當下字幕。

開始 V2 會停用 V1 自動翻譯，避免同時跑兩條模型流程。每次重新開始收音都必須重新手動同意，不沿用字幕自動模式或上次收音同意。

## 3. 延遲、停止與限制

- 第一段須先累積 **12 秒音訊，再加上辨識、翻譯及網路等待時間**；尚未測得可保證的總延遲。
- 一次只處理一段；**辨識期間不新增錄音，因此片段之間可能有未收錄空段**。預設 2 段不代表完整連續的 24 秒內容。
- 暫停、跳轉、切分頁、視窗離開前景、廣告或非 1 倍速會停止收音；未完成片段會丟棄。可按 popup「停止分頁收音」，或面板「停止收音／關閉」。
- 停止不能保證供應商免計費；已送出的片段、失敗或取消仍保守計入使用量。錯誤不自動反覆重送。
- 目前僅支援英文音訊與一般 YouTube 影片頁，不保證直播、無法回看的內容或所有 Chrome／YouTube 更新版本可用。
- 本機需有 FFmpeg／ffprobe；後端會檢查完整 WAV/WebM、2 MB／15 秒上限與時間一致性。原始音訊不落地保存；每日計數會保存，停止工作後清理工作中的音訊狀態。音訊仍會送至模型供應商，不能視為完全離線處理。

## 4. 驗證範圍

已通過後端／路由 mock 測試，以及本機記憶體產生 WAV、WebM 的 ffprobe 驗證；測試沒有將音訊送交付費模型。**尚未進行真實付費辨識與翻譯驗收，辨識品質、專業術語表現、實際延遲及 Chrome 端到端穩定性仍需小額實測。** 第一次請維持 2 段，確認結果與費用後再調高上限。

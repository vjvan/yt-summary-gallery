# 觀看翻譯：全本機模式（v13／擴充功能 0.5.0）

## 現在怎麼用

1. 在此專案先完成 `npm run build`，再執行 `npm run watch:local`。終端機需保持開啟。
2. 本機觀看頁是 <http://127.0.0.1:3000/watch>；狀態應顯示「全本機」。
3. Chrome 擴充功能頁重新載入 YT Summary，確認版本 **0.5.0**，再重新整理 YouTube 影片頁。整片排程、進度與長字幕分頁在擴充功能，逐句快取與品質檢查在本機後端；兩端都需更新，但不需重新安裝或重貼配對碼。
4. 已配對過不需重貼碼。打開擴充功能，確認顯示本機 `qwen2.5:7b`、不限總批數，再同意本機處理並開始。**本機整片預譯預設開啟；載入原文後即逐批處理，暫停影片或切到其他分頁仍會耗用本機 CPU／GPU、記憶體與電力。**取消 Popup 的整片偏好才改成播放附近（nearby）模式；功能本身與自動啟用其他影片仍需明確啟用。
5. 有原文字幕優先走文字翻譯。沒有字幕才另外手動同意「分頁收音」；收的是該分頁聲音，不是麥克風。

`npm run watch:local -- --check` 只檢查模型檔與本機服務，不啟動推論。

## 為什麼分批，還會不會播到一半停？

- **每批最多 8 段**：一次向後端要求處理的字幕段落數，不是 8 秒、8 分鐘或金額。本機模型在批次內逐段翻譯，避免把多句合併後錯配時間；回傳可以包含成功句及個別失敗句。
- **總批數上限**：舊雲端模式防止 API 不斷計費的保護；雲端擴充預設 10 批，後端另外有單片／每日次數上限。全本機不套用這些付費總量上限。
- **整片（full）模式**：本機同意並啟用後預設使用，先處理目前播放位置，再依原文順序補齊；暫停、播放結束或分頁在背景都不代表停止預譯。不是把一整支影片塞成一個超大請求。
- **播放附近（nearby）模式**：取消本機整片偏好後使用；所有雲端工作也維持 nearby。只處理播放位置附近與有限預取，暫停／背景時不派新字幕翻譯工作，不主動從頭翻完整片。雲端已送出請求即使取消仍可能計費。
- 每支工作仍一次最多一個待處理請求；每批大小、逾時、取消與安全大小上限保留。模型關閉、連線失敗、工作過期或安全錯誤仍可能停止排程，必須按畫面提示處理；不限總批數不是不會失敗的保證。
- 「80／221 句已就緒」按**實際已成功的原文 ID**計算，包括匹配的既有快取，不是請求次數乘 8，也不代表從頭連續翻到第 80 句。末批不足 8 句仍照實計算；只有 221 句全數成功才標全片完成。失敗句不以原文或空白湊入進度。
- 7 分 31 秒或其他影片時間不是固定門檻；同樣 10 批在不同語速／字幕切分下，涵蓋時間不同。本機已不靠把雲端額度調大來延長觀看。

## 本機品質拒收、逐句保留與恢復（v13／0.5.0）

- 影片 overlay 直接標示工作階段的實際模型。只下載另一個模型，不會讓連到 3000 的擴充自動換模型；以 Popup／overlay 顯示為準。
- 每批仍最多 8 段；每段最多一次品質修復，最多 16 次本機推論、90 秒總期限的保護不變，沒有無限重試。已有成功快取的句子不再推論。
- 後端明確回傳 `LOCAL_TRANSLATION_QUALITY` 時，**只拒收失敗句，不丟棄同批已成功的句子**。例如 7 句成功、1 句失敗：保留 7 句中文及成功快取，僅失敗句顯示原文／未翻譯；失敗句不算成功、不寫成功快取。若只收到舊式整批錯誤而沒有逐句結果，也不憑空宣稱其中句子成功。
- **本機整片模式**先跳過含失敗句的批次，繼續其他未完成批次，不反覆自動重送。其餘處理完仍有失敗時會明示未完成，稍後由本人按擴充功能「重試目前區段／重試下一個失敗區段」，或本機觀看頁「重試失敗批次並繼續整片」；只補缺少成功快取的句子。暫停也能執行整片模式的手動重試。
- **nearby 模式**仍按播放位置工作。回到失敗區段按「重試目前區段」即可，不需全部重新啟用；暫停時只排定，播放後才送出，離開區段會撤銷尚未執行的重試。再次品質拒收仍需本人選擇，非品質暫時錯誤沿用有界處理策略。
- 401／工作過期／模型或模式改變／雲端費用上限等仍須處理，不能靠隔離錯句繞過。連線、逾時與其他模型錯誤不當作品質部分成功。
- **只有專名或合法技術名稱的句子可能完整保留英文**，例如原句只有「OpenArt, Higgsfield.」。這不是漏譯，也不能只因沒有中文字就判定失敗；但一般英文敘述不能因此冒充已翻譯。名稱保留與成功進度不代表所有語意已通過人工審校。

## 有完整原文字幕：預先翻完整片

v13 本機觀看頁與 0.5.0 擴充功能，在**取得原文、後端確認全本機、本人同意並啟用**後預設逐批翻完整片；單純開啟頁面或尚未同意不會啟動模型。擴充的自動模式是另外的 opt-in，開啟後其他已啟用影片也可能各自預譯。

- 不需播放影片，**暫停或切到其他分頁仍會處理原文、耗用本機算力**；沒有下載影片或錄音。請保持來源頁與本機服務開啟。電腦休眠、Chrome 凍結／丟棄背景分頁可能中斷，並非保證持續運作的伺服器佇列。
- 快轉／點逐字稿不取消整片模式正在處理的批次；完成後優先處理最新位置，再補齊其他缺段。nearby 模式則保留跳轉取消舊位置工作的行為。已完成字幕仍依原影片時間顯示，背景預譯不會自行推進字幕頁碼。
- 後端以**影片原文、模型、翻譯版本與術語設定**匹配逐句快取。成功句可跨重新載入使用；新 session 載入匹配的 `cachedCues` 即計入進度，全片快取齊全時不新增翻譯請求，不冒充剛進行新模型推論。取消／過期工作的遲到結果不套回新影片。
- 每批最多 8 段、同一工作只處理一批；部分成功先保留，品質失敗句留待本人重試，其餘照常補齊。進度停在未全數成功時不能宣稱全片已完成。
- 雲端模式不使用整片背景入口，仍保留原同意、nearby 範圍與費控；原文字幕、YouTube 分頁收音、Discord 收音也不是同一條排程規則。
- 停止、撤回同意、離開影片或關閉／重新整理頁面會取消工作。擴充切到**原文模式**會取消尚未完成的請求並停止新增翻譯，保留已完成字幕；本機觀看頁可用停止工作。只是暫停播放器不等於撤回全片預譯同意。
- 全數已就緒後，快轉到有原文字幕的段落可直接顯示已完成譯文；沒有原文字幕的空白區間不會憑空補字幕。擴充提供本人點擊的「下載完整雙語 SRT」，保留原時間及完整原文／譯文、專名，不使用畫面分頁或摘要；缺任何句子時不提供「完整」下載。

## 模型與費用

- 翻譯：本機 Ollama `qwen2.5:7b`。
- 英文語音辨識：本機 whisper.cpp＋多語 `ggml-small.bin`，再交給本機翻譯模型。Whisper 的 `translate` 不是英翻繁中，此處使用原文辨識再翻譯。
- 預設模型目錄：`~/Documents/Codex/local-models`，約 5 GB 級模型與執行環境，首次下載需要網路。
- **觀看翻譯與收音不產生雲端 API 費用**；仍使用電腦記憶體、GPU／CPU、電力。YouTube 播放及取得原文字幕仍需要網路，並非整個產品離線。
- 原有「整片摘要／圖卡」舊管線沒有改成本機；不要把此頁的本機模式解讀成全專案所有功能都免費。
- 本機模型失敗時明確報錯，**不會自動切回付費 API**。Ollama 啟動器設 `OLLAMA_NO_CLOUD=1`、僅聽 `127.0.0.1:11434`。
- 本機與雲端快取依模式／模型／翻譯版本區分；本機逐句快取另比對影片原文與術語，不能混用不相符結果或冒用以前的雲端結果。

## 收音限制

本機可不限總段數，但每段約 12 秒。現階段為實驗性分段辨識：辨識期間不新增錄音，因此會有空段與延遲；不是完整連續直播轉錄。暫停、跳轉、廣告、切分頁或非 1 倍速會停止，之後須重新手動同意。介面只保留近期收音結果，避免長時間記憶體無限增加。

以上是 YouTube 分頁收音支線。Discord Chrome 的連續收音使用獨立流程，請參考 [Discord 操作說明](discord-live-local.md)，不要混用兩者的操作或驗收結果。

## 台灣用語與逐句品質

- **v14（2026-09-06）**：字幕的講者標籤（例如 `Drew Brucker (27:13)`）會自動當成該片的保留詞，模型被要求原樣保留人名與時間戳；修一次仍音譯時照樣接受，不會因此拒收。大寫語氣詞（Yeah、Dude、Man、Bro 等）不再允許留在譯文裡。原文的阿拉伯數字、百分比、時間戳若在譯文消失，會用同一次修復機會要求補回；修不回不拒收。台灣用語改為程式內整理過的對照表（信息→訊息、用戶→使用者、默認→預設、伺服器、記憶體、品質、老兄、Podcast 等），刻意不用 OpenCC 片語表，因為它會把「連接」改成「連線」這類普通詞。字庫的 Obsidian 真身與套用工具在 `~/aivan/projects/yt-translation-tool/glossary/`。
- 簡轉繁只處理字形，不足以解決用語與語意。字幕指令另指定台灣繁體中文：「video → 影片」、「video generation model → 影片生成模型」、「image generation model → 影像生成模型」，一般 image/photo 依情境使用「圖片／照片」。不一律把所有「圖像」硬換成同一個詞。
- 保留專業節點、品牌及程式識別名稱；術語表的保留詞優先於預設翻譯詞。可在 `/glossary` 設定專業譯名與風格。
- 本機改為每次只翻一段原文，由程式保留原始 ID 與時間，避免小模型把整批重新摘要、補完後句後塞進錯誤時間點。代價是跨句語境較有限；未完句、代名詞與歧義仍可能不自然，不能當作人工專業審校。
- 新版快取版本不重用先前的錯位譯文，無需清除整個資料庫。更新後請重新整理觀看頁或 YouTube 頁，重新載入並啟用字幕。

## 長字幕：完整翻譯，分段顯示

不為了縮短字幕而要求模型摘要、刪字或改寫原意。影片上的長字幕使用**顯示分頁**：在同一段原字幕的起訖時間內，依序顯示較短文字；暫停時停留該頁，跳播時重新計算。這是顯示層的時間分配，不是逐字語音強制對齊。

- 右側同步逐字稿保留完整原文與完整模型譯文，分頁不改變資料或重新呼叫模型。
- 雙語、繁中、原文模式仍可切換；平台名稱如 OpenArt、Higgsfield 保留英文，不因排版而改成中文。
- 原字幕本身語速很快時，即使分頁仍可能來不及閱讀；可按「暫停看本句全文」查看完整原文與模型譯文，收合不會自動恢復播放。也可查看右側完整逐字稿，不會偷偷放快、刪去內容或自動暫停影片。全螢幕須先縮回才有全文按鈕。
- 本機頁更新後重新整理；YouTube 原網站的顯示修正則需重新載入擴充功能，再重新整理 YouTube 頁。既有配對碼不需要重貼。

以上改善不代表模型譯意已完全正確；斷句、漏義與語意誤判仍需另行驗證。先前模型實驗曾發現 `99%` 被概括成「多數」、`image 2` 漏掉版本數字。僅加強提示詞沒有修好，未採入該實驗；不能把顯示層完整保留文字當作模型完全不漏譯的保證。

## 已啟用卻沒有中文時

「已啟用」代表已同意開始，不保證每句推論成功。先分清**尚未排程／正在翻譯、品質拒收、工作停止、合法專名保留英文**，不能只看有沒有中文字判斷。

1. 查看模型名稱、具體錯誤與已就緒／失敗句數。個別品質拒收保留原文，不遮掉同批已成功中文；整片模式會先繼續其餘批次，不自動無限重試失敗句。
2. 稍後本人按失敗重試。**整片模式不需播放也可重試；nearby 模式暫停時只排定，播放後才執行**。重試只補尚未成功的句子，不需重新勾同意。
3. 配對、工作過期或模型改變時，依提示重新載入影片與原文；模型未執行、連線或逾時錯誤仍須先排除，不當作一般品質失敗跳過安全限制。
4. 原文只有 OpenArt、Higgsfield 等保留名稱時，合法譯文仍可能是英文；一般英文敘述則必須翻譯，不能用原文冒充成功。任何失敗都不會自動切到雲端。

## 重啟與故障檢查

- 3000 已有服務：不要再啟動第二份；先停止自己開的那份。
- 「本機 Ollama 未啟動」：執行 `npm run watch:local`，等待模型服務就緒後重新載入影片。
- 擴充仍顯示「10 批」：確認已重新載入擴充功能 **並重新整理 YouTube**，再測試連線。不要靠把雲端限制填成巨大數字代替本機切換。
- 硬體／模型品質：字幕仍可能有術語、斷句或語意錯誤，可在術語表保留節點英文名稱；不保證逐句專業審校品質，也不是零延遲。

## 登入自啟（2026-09-08）

3000 本機服務（Next start、Ollama、3111 轉址）由 launchd 使用者代理程式 `com.vjvan.yt-summary-gallery` 管理：登入即啟動，程序非正常結束會在 15 秒內自動重啟（`KeepAlive.SuccessfulExit=false`）。管理指令都在 `scripts/launchd-3000.sh`：

```sh
scripts/launchd-3000.sh status      # launchd 狀態 + 3000/3111/11434 是否在聽
scripts/launchd-3000.sh restart     # 部署新 build 後用（kickstart -k）
scripts/launchd-3000.sh stop        # 停止並取消自啟（plist 保留）
scripts/launchd-3000.sh install     # 重新寫 plist 並 bootstrap
```

log 在 `data/launchd-3000.log` 與 `data/launchd-3000.err.log`。plist 只設 `PATH`、`HOME`、`LANG`、`WATCH_PROCESSING_MODE=local`；`.env.local` 仍由 Next 從專案目錄讀。

**只開服務，不自動生成**：`instrumentation.ts` 開機時的 `recoverZombieJobs()` 預設**不再續跑**中斷的舊摘要管線（翻譯／摘要／圖卡會呼叫模型），只把它們標成可重試的 error，已完成的轉錄與翻譯都留在資料列上；重新提交同一連結會從斷點接續。要恢復舊行為，在 plist 的 `EnvironmentVariables` 加 `YT_SUMMARY_AUTO_RESUME=1` 再 `restart`。影片庫字幕工作（本機）本來就不自動續跑。

已驗證：bootstrap 後 3 秒回 200；`kill -9` next-server 後 3 秒由 launchd 拉起新程序；`kickstart -k` 2 秒內回 200。**真正的重開機／登入尚未實測**，下次登入請跑一次 `status` 確認。

部署流程改為：備份 `data/summaries.db` → 確認沒有 processing／burning／持鎖列 → `npm run build`（build 期間服務仍在跑舊版，`.next` 會被覆寫；要保守就先 `stop`）→ `scripts/launchd-3000.sh restart`。

## 進階設定（皆為伺服器設定，不放到擴充功能）

- `WATCH_LOCAL_MODELS_DIR`：模型根目錄。
- `WATCH_LOCAL_MODEL`：已安裝本機模型名稱，預設 `qwen2.5:7b`；不接受雲端標籤或網址。
- `SUBTITLE_REVIEW_MODEL`：語意校訂專用的本機模型，沒設就同 `WATCH_LOCAL_MODEL`。校訂一次只跑一窗、量少，可以換大一點的模型；2026-09-08 用 `scripts/review-probe.ts` 在兩個真實視窗實測：`qwen2.5:7b` 每窗約 2 秒、會殘留英文與把 £5,000 翻成五萬；`translategemma:12b` 約 8 秒、數字與語意最穩但會自作主張補貨幣（美元）；`qwen3.8:27b` 約 34 秒、最準；`qwen3.5:9b` 是思考型模型，輸出額度會被思考吃光，不可用。用 launchd 跑 3000 時要在 install 當下設：`SUBTITLE_REVIEW_MODEL=translategemma:12b scripts/launchd-3000.sh install`。
- `WATCH_LOCAL_WHISPER_MODEL`、`WATCH_LOCAL_WHISPER_BIN`、`WATCH_LOCAL_OLLAMA_BIN`：需要絕對路徑。
- `watch:local` 強制 `WATCH_PROCESSING_MODE=local`，不會因為舊 `.env.local` 有 API key 而改用雲端。
- `WATCH_PROCESSING_MODE=cloud` 只有營運者明確使用一般啟動指令設定時才生效；其費用同意與額度限制仍存在。
